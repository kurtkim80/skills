# 报告模板

本文件是 `skill-description-audit` 审计报告的**逐字骨架**，落盘 `DESCRIPTION-AUDIT.md` 时整体照抄（含下面两侧的 `~~~` fence 标记，不另包一层）。

标注 `<!-- …:begin -->` 的块（报告头两行、「一、判据集结果」表的作答行）由 `python3 scripts/render-criteria-set.py` 从唯一源 `criteria-set.yaml` 渲染，**本文件与 SKILL.md 各有一份、两处同进同出**——改判据只改 YAML，然后跑 `--write`；`--check` 两处一起比对，**手改任一处即红**。

解释器 / 环境 / 门禁命令的说明从 `SKILL.md` 正文继承，本文件不重复。

下列为报告正文结构（落盘时勿包一层多余的外层 fence）。推荐文案用缩进代码块写出即可：

~~~

## 五、问题

1. **[高/中/低/信息]** <标题>
   - 现象：…
   - 证据：…
   - 影响：…（**写用户视角的后果：改了会怎样 / 不改会怎样**；不要写「属 A/B 类」这类分类自述）
2. …

（无缺陷则本节正文为「无」。）

**两条硬约束**（2026-10-04 起，判据集反转「档位实源」后新增）：

1. **本节各条发现的最高档 ＝「一、判据集结果」`SEV-01` 行的值。**
   档位的唯一实源是**发现**（依据见 `references/criteria-governance.md` §8.20），
   不是各题 `band` 的复算。校验器从本节抽档位与 `SEV-01` 行**硬比对，不一致即硬失败**。
2. **发现有三种等价写法**，任选其一（校验器三种都认）：
   `1. **[低]** 标题`（编号形）／`### [中] P1 标题`（H3 形）／`- **[高]** 标题`（破折号形）。
   **形态清单的唯一源是 `scripts/audit-criteria-set-check.py` 的形态表 `FORMS`**（本模板关心的三条是 `report-finding.ordered` / `.h3` / `.bullet`）——本模板不另定一份。
   ⚠ **别在发现下面再写带档位的编号子清单**——那会被当成顶层发现（假红）。

> **不许填 `无` 来躲过这条**：若确实有发现（哪怕它不对应任何一道判据题，例如判据集/契约自身的缺陷），
> `SEV-01` 就照实填实档。填 `无` 会让报告最重的一档凭空消失，且**不会有任何门禁告诉你**。
