# 判据增删治理（停手线）— criteria lifecycle

**这份表是 `agent-skills` 库的现状记录，不是给使用方的执行指令。** 表中「现状」列写的是
该库**自己仓内**的脚本路径与档位——别的项目装了本技能后这些路径不存在，不要照着跑。
（跨仓要执行的命令，只写在本技能的「报告文件」「工作流」两节。）
解释器同理：示例写 `python3` 是 Linux/macOS 面，**Windows 用 `python`**。

适用对象：`description` 面（或任何质量判据）的新增、降级、删除。来源：description 边界治理四轮审计
（`audits/2026-10-02-skill-boundary-separation-plan-v3-audit.md`、
`audits/2026-10-03-boundary-governance-fresh-research.md`）＋ 真源仓坑 p000060。

## 2. 新增判据的唯一合法触发条件（三者缺一不可）

1. 现有实测闸报出**可复现 FAIL**（能复跑，不是印象）；
2. 落盘**证据行号**（报告／命令输出里能指到具体行）；
3. **独立方审计通过**（审计员 ≠ 判据作者，见硬约束 6）。

缺任一条 ⇒ 不新增。改为在报告「建议」节登记为候补项，等条件齐备再议。

## 2A. 判据集升版的触发条件（C-4 的前件 · 2026-10-05 补）

C-4 只规定「升版 ⇒ 引用旧版本的轮次失效」，**没规定什么改动必须升版** ⇒ 同一批改动，
两个人能一个升一个不升，还没法判谁错（本轮就发生过：给 `STR-01`／`LEN-01` 加 `band` 后
以「题面与答案空间未变」为由不升版）。补齐如下：

| 改动面 | 升版？ | 为什么 |
|---|---|---|
| 题面 `q`、答案空间 `answers`／`type`、组别 `group`（A／B／derived）、`cell` 格绑定、题的增／退 | **必须** | 直接改变「这道题在问什么、能答什么」 |
| `band` 的**有无与映射值**、`no_severity` 的有无 | **必须** | 它决定「答某个值意味着哪一档」——改它＝改判定的含义，旧报告的答案在新包络下不再可比 |
| `explain`／`source`／`band_note`／`band_source` 的纯措辞、注释、渲染格式、报错文案、夹具 | **不升** | 判定输入与答案空间都没动，升版只会把所有在册报告无谓作废 |
| 判据集**结构**（新增键、闭集变化） | **必须** | 消费方（校验器／渲染器）口径变了 |

动作：版本号唯一源＝`criteria-set.yaml` 的 `version`；升版后旧头行的报告由
`scripts/audit-criteria-set-check.py --gate-answers` 归入 B 类迁移清单（不是「答错」），按 §1 的迁移底线处置。


## 3. 判据层级的选择：能用实测闸判的，不要用措辞判

| 层 | 形态 | 例 | 适用 |
|----|------|-----|------|
| L1 机检 | 脚本 + 落盘证据 + 退出码 | `notfor_refs()`、`trigger-confusion-test.py` | 首选 |
| L2 软告警 | 脚本只报告不拦门 | `description-lint.py` 的 WARN | 有信号但无稳定判据时 |
| L3 措辞规则 | 正文写规范，靠人读 | 「NOT for 按能力划界」 | 仅当无法机械判定 |

**一条实测闸的合格线**：判据的判定输入＝执行事实（命令输出、回执、快照），不是「谁记得上次怎么判的」。

## 4. 已知反模式（本库四轮实证，同一病根）

| 反模式 | 后果 | 实证 |
|--------|------|------|
| 新开判据与既有闸重复 | 层叠、信号噪声 | 要新开 description 判据却与 `forward_refs` 闸重复 |

| 指纹行被反引号包裹 | 硬闸**静默失效** | p000060 |
| **先立判据、后量触发率** | 判据退化成噪声源 | 两次实证：本库 `H2 省略前缀` 12/12 全误伤；本技能 `COV-03c` 61 件触发 59%。**见 §6.1** |

| **`str.replace()` 未命中当成功** | 整节没写进去却显示「ok」 | 当天「逃逸登记」节因此丢失，grep 计数才发现。**replace 后必须断言命中**。**见 §6.9** |

## 5. 回滚判据（同样可复跑）

某判据报出后，若全库真实改动数 `a(D) == 0` ⇒ 该判据删。硬失败优先于软告警删除。
删判据时同步更新本文件第 1 节现状表，并在审计报告留一行删除理由。

## 6. 判据怎么算被证过（验证方法 · 2026-10-03 全量实测沉淀）

**核心原则：判据不是「写出来」就算数，是在真实样本上被证过才算数。**
当天两次退化（本库 `H2 省略前缀` 12/12 全误伤；本技能 `COV-03c` 61 件触发 59%）
**共性都是「先立判据、后看触发率」**。以下每条都对应一次实测。

### 6.1 立之前：先量触发率
- **≥20 件真实技能**，量它触发几次。
- **超过 1/3 ⇒ 它不是判据，是噪声源** ⇒ 要么收窄到「能产生可观察差异」的一小撮，要么不立。
- 语料要有代表性：**外部第三方技能至少占一半**。只测自家技能会系统性偏宽——
  同族 description 雷同，审计员会拿同族当参照系，于是族内一致、整体偏宽。

### 6.1b 两个必须先修的测量洞（2026-10-03 实测各踩一次）

**洞一：同族同形态的重复命中，把触发率灌了水。**
`COV-03c` 在 24 件上触发 16 件（0.67），审计员核出**其中 lark 子技能一族 7 件理由高度同型**
（「正文要求先完成认证/scope/身份指定，desc 未声明」）⇒ **那是同一条发现被数了 7 次**。
**修法**：触发率的分母不是「件」，是「**去重后的独立形态数**」。
同族同形态合并计 1。**否则一个家族会把指标拉爆，而真实信号只剩一条。**

**洞二：语料不含某约定时，触发率量的是「样本来源分布」，不是判据质量。**
`VOL-02`/`VOL-03` 实测 0.375（超线），但核出：**全部 77 件外部技能里含 `lastUpdated`/
`refreshInterval` 的是 0 件**——外部生态**压根不用这套约定**。那 9 次「是」全在说
「这个生态不这么写」，**对判据写得对不对零信息量**。
**修法**：量某判据的触发率前，**先确认语料里存在该判据的适用对象**；不存在则该次测量
**不产出结论**（记「语料不适配，不可评」），而不是记一个高触发率。


- 当天合成了 14 件夹具，**全是我自己设计的**——它们只测出了**我以为存在**的缺口。
- 换成 77 件真实第三方技能后，14 件里挖出 6 处逃逸，**其中两种形态我完全没预料到**。
- **结论：判据的鉴别力只能用「我没见过的输入」测。**

### 6.3 双向：每条夹具必须有两条腿
- 「能报出问题」**不够**。必须同时证明「合规件不误报」。
- **只会报警的闸会被绕过**——本库 `H2 省略前缀` 就是这么退场的。
- 配套：**判是却举不出合格话语**时，该题在该件上作废（见 6.4）。

### 6.4 「逼不出证据」即信号
- 判「是」却**举不出 ≥2 句合格话语**（话语 ＋ 路由/执行如何改变）⇒ **该判据在这件上不成立**。
- 这是**判语义判据唯一便宜的检测器**：不需要真值，只需要举证要求本身。
- 当天在真实样本上累计触发 **12 次**，每次都指向判据文本的真缺陷（措辞歧义、缺面、口径冲突）。

### 6.5 期望值必须从判据文本推导
- **不能凭「直觉上正确答案」。** 当天凭直觉写的 4 处期望值，盲跑后**错了 3 处**。
- **判据与直觉冲突时，改判据（走独立审计），不改期望值。**
  写反了就是让判据迁就写夹具的人。

### 6.6 先答后看
- 期望答案与夹具内容**分节存放**，审计员**先答完再翻**。
- **盲跑的证据形态**：审计员在某一格答的是「订正前的错值」⇒ 既证明没泄题，
  也证明**歧义是真的被措辞误导**、不是执行者不小心。

### 6.7 独立审计要问「有没有我不知道的问题」
- 而不是「有什么问题」——前者才逼出**自己没想到的**缺陷。
- 当天四轮独立审计，每轮都抓出我自审漏掉的真缺陷（判据文本自相矛盾两次、枚举不穷尽、
  分类混淆两处）。

### 6.8 解析层铁律：唯一源，自造解析＝双源
- 当天两次踩：① 自己拼指纹（漏了真源的 `body.strip()`，实算值与真源差一截）；
  ② `text.split('---')` 切分 frontmatter（把正文里的分隔线也切了，判据集静默解析成 0 条）。
- **一律 import / 复用真源函数**，不重实现。**「差不多一样」的解析就是新的双源。**

### 6.9 静默失效六型（当天的清单，写下来备查）
| 型 | 症状 |
|---|---|
| 源表单元格含未转义 `\|` | 列被拆错，判据被吞，**无报错** |
| 判据 ID 长度不一（`STRUCT-` 6 字母 vs `COV-` 3 字母） | 正则漏匹配，**静默少一条** |
| ID 带小写后缀（`COV-03a`） | 同上 |
| 判据表被说明段落**从中间截断** | 后半截掉出表，而条数自校验照样通过 |
| 自校验与解析**用同一条正则** | 二者同源同盲区 ⇒ 自校验是**同义反复** |
| `str.replace()` 锚点未命中**不报错** | 整节没写进去却显示「ok」 |

**共性：不报错，但判据没了。** 对策：**每写一个解析器，配一条变异断言**——
把结构改坏，闸必须红。**「没报错」不是「对」的证据。**

### 6.10 误伤比漏报更该先治
- 当天新校验器一跑，**23 件被判「指纹失配」**，而它们的指纹**完全正确**——
  只是指纹行带了尾注 / 用了半角冒号。
- 若不放宽正则，这 24 件会变成**永久假阳性**；我甚至差点把「23 件指纹失配」当重大发现汇报出去。
- **判据若会稳定地给出错误答案，它比「没结论」更坏**——它教会使用者忽略这一类告警。

### 6.11 停手线补充
- 判据**连续两轮实测触发率 > 1/3** ⇒ 不再改它，直接**删或降为人工项**，不要继续调措辞。
- 判据集**长期零命中** ＝ 可能不可达（如已删档的「不适用」）⇒ 查它有没有可达路径，没有就删。

## 7. 能力预设越界维的定档表（SKILL.md §7.7 原文归档）

### 7.7 判据前提归属（能力越界 · v1.15.0）

`FOR-01` 管 description 面的**能力外借**（2026-10-04 整题重写，此前管的是「点名了他件、接收方是否一定持有」，已作废）；本组管**正文判据表**里的**能力预设**——更隐蔽，且正则查不到。

**为什么需要这一维**（实证与「能查/查不了」的对照）→ `references/patterns.md` §7.7 论证段
**逐条填空，输出分类判断，不要求推理**——对被审技能维度表里每一条 `[M1]`/`[M2]`（及其判据文本）填三格，**每格从固定枚举里选**：

| 字段 | 枚举 | 取法 |
|---|---|---|
| 前提 | `无前提` / `本技能自带` / `通用能力` / `被审仓提供` / `其他技能提供` | 跑这维依赖什么**外部**东西。**不依赖任何外部前提**（纯结构、纯文本形态）填 `无前提` |
| 归属 | `自足` / `有条件` | **由前提推导、不另填**：`无前提`/`本技能自带`/`通用能力` ⇒ `自足`；`被审仓提供`/`其他技能提供` ⇒ `有条件` |
| 缺前提时 | `静默跳过` / `误报/漏报` / `硬报错` / `未验证` / `不适用` | 只描述**事实**。**须取自可复现的实测记录；无实测填 `未验证`，`自足` 维填 `不适用`**（无外部前提可缺）。**`有条件` 维不得填 `不适用`**——缺前提必有后果，无后果即 `自足` |

**定档规则**（按顺序判，命中即止）：

| 序 | 条件 | 档 |
|---|---|---|
| 1 | 该前提**属该技能职责范围内**（如「转发给 X 技能」本就是它的活） | **通过** |
| 2 | 前提来源与职责范围**矛盾**（前提靠别的技能，而它又该自己判） | **[H]** 交人裁定 |
| 3 | `有条件` ＋ 缺前提时 = `静默跳过` | **[中]** |
| 4 | `有条件` ＋ 缺前提时 = `误报/漏报` / `硬报错` | **[低]**（失败可见，不会骗过人） |
| 5 | `有条件` ＋ 缺前提时 = `未验证` | **[中]**，并在报告注明「未证实的越界按最坏档处理，须补实测」 |
| 6 | 全 `自足` | **通过**，不逐行报 |

顺序不可换：规则 1 优先于 3/4/5——**先问是不是它的职责，再问缺了会怎样**。反了会把「这技能本来就该管的事」判成缺陷。

**与 `FOR-01` 的分工**：`FOR-01` 判「description 是不是在拿别的技能充实自己（能力外借）」；本节判「正文判据预设了什么、缺了会怎样」。**两者都指向同一件事——别假设用户持有你不知道的东西**，但一处看描述、一处看判据表，不可互相替代（实测：某技能的越界在 description 上完全合规，全文只在正文维度表里）。

> 与 `FOR-01` 分工——`FOR-01` 只管 description 面的能力外借（实证：某技能 description 完全合规，越界只在正文维度表里，

## 判据集自身的已知缺口（规则 11 登记 · 2026-10-03 v1.16.4 起）

以下是**判据集这条轴**上的缺口，不是操作失误。错法→改法类材料在 `patterns.md`，两者不混搭。

以下三条**按规则 11 登记不修**——它们不是措辞问题，换措辞解决不了；等有更多可复现 FAIL 再议。

1. **「能力清单」这个抽象在大技能与外部技能上不可枚举**。真技能实测：
   `test-data-generation` 正文 476 行、可枚举能力上百项；vendor 的 `ponytail-review` 更是
   **同名多入口**（`ponytail`／`ponytail-review`／`ponytail-debt`…），其 `description` 讲的是**家族**、
   入口路由写在正文 ⇒ **逐能力枚举根本抽不出全集**。已把要求从「全集」降为「被引用的清单
   ＋写明来源与抽样边界」，但这只是**止损**（不假装有全集），**没有解决根因**。
   可能的改法（未验证）：把判据从「逐能力判」换成「按触发维度判」（WHAT／WHEN／反触发／
   调用授权／验收，五个维度各分判）——一次解决「异质」与「不可枚举」两个问题。**改前须先有可复现 FAIL。**
2. **集内异质会让「任一」失真**。`security-scan` 的未覆盖清单里 10 项是隐含约束、1 项是反面护栏
   （`trust`）——那 1 项制造误触发倾向、9 项不会，**集内多数表决没有意义**。
   根因同 1：「能力」与「触发维度」是两种东西被塞进了一格。
3. **本地规则集被当成通用口径**。`prerequisites`／`required_before` 是本仓 AGENTS 独有的判据类别，
   外部技能上没有；照搬会让审计员去找不存在的东西。**判据集应声明适用范围**（本仓 / 通用），
   适用范围外的判据对相应技能应填「不适用」而非硬判。

**另有一条已证伪的假设已删除**：初版写「`COV-01=是` 时 `COV-03a/3b` 填 `不适用` 先行」——
实测 `skill-eval` 的 `COV-01=是(0.75)` 同时 3a/3b 判「是(0.72/0.70)」：**覆盖完整不等于无覆盖缺口**。

**这一层当前的成熟度**：在小样本上（ground-truth 沙箱 4 件 ＋ 真实技能 6 件）已能稳定给出
可复核的判断、置信脱离「恒卡同一值」；但**在大技能与外部技能上仍有实质缺口**（见上三条）。
**结论是「继续用、继续攒证据」，不是「否决」**——它本就是给技能加的一层能力，
缺口意味着「这里换个问法会更好」，不意味着「这层不该存在」。

**不同业务域**——按前缀合并＝在测「厂商模板」，不是测「一个形态」。

**所幸两种分母下结论一致**（user-invoked 都是 1.9%、有 references/ 都是 27%±1）⇒
结论对口径不敏感，这是这次返工没翻车的唯一原因。

| 量 | 结果 | 怎么读 |
|---|---|---|
| `COV-01`/`COV-03a` 新「user-invoked ⇒ 不适用」档的**适用面** | **10/499 ≈ 2%** | 语料里 user-invoked 技能只占 2% |
| `VOL-03` 新「无已外置表 ⇒ 不适用」档的适用面 | 134/499 ≈ 27% | 有 `references/` 的件占近三成 |

**结论一（推翻了我的一个前提）**：我给 `COV-01`/`COV-03a` 补「不适用」档时，
理由是「审 user-invoked 技能必然假 [中]」——**方向对，但适用范围比想象的小两个数量级**。
外部生态里 user-invoked 只占 2% ⇒ **这一档是窄修补，不是系统性改造**。
写进判据集的 `band_note` 与正文之前把它讲得太重了（暗示它是常备路径）。
**低触发率不是废判据的理由**——§6.1 的 1/3 是**上限**（防噪声），不是下限（防冷门）；
但它确实说明这一档的收益面窄。

**结论二**：`VOL-03` 的「不适用」档适用面 27%——**这一档是常备路径**，不是边角。

**结论三（本轮最重要的一条）**：`SEM-01`（名称语义）与 `COV-01`/`COV-03a` 的「否」档
**机械量不出来**——「单段泛名」「标志性能力是否全覆盖」都是语义判断。
`corpus-trigger-rate.py` 因此**明确拒绝为它们出数**，只列清单交人工逐件量。
**这不是脚本偷懒，是「绝不用文本特征猜一道语义判据的触发率」**——
猜出来的数字会像实测的一样被下一个人引用，而它是假的。

**§6.1 的 1/3 线只管一个方向**（2026-10-04 独立审计核实）：治理文件只写
「**超过** 1/3 ⇒ 不是判据、是噪声源」——它是**上限**，防的是「在多数样本上都报、分不清」。
**全库没有「低触发率即废」的表述** ⇒ 2% 不构成废判据的理由。
更根本的是量纲不同：加「不适用」档改变的是**答案空间、降低误报率**，
而 1/3 量的是**区分度不足**，二者不是同一件事。

**未被测到的那一半（诚实记下）**：本轮只量了**适用面**（这一档会被用到多少），
**没量收益面**（「不量的话假 [中] 会出现多少次」）。脚本测不了后者——它要对照
「若不判该档会怎样」，那是反事实。⇒ **「2% 说明面窄」不等于「这一档不值得加」**：
成本是一个枚举值，收益是本件已实证的那次假 [中] 消失。

### 8.6 `SEV-01` 复算取上界 ⇒ 报告自报档位系统性虚高（**迁移批次实证 · 2026-10-04**）

- **现象**：把 19 份存量报告迁到判据集后，`SEV-01` 行被要求填「按各题 `band` 复算的
  最高档、区间取上界」。于是同一份报告里出现**两档并存且互相矛盾**的写法：
  判据集块写 `高`/`中`，而「五、问题」节列的实档是 `[低]`。
  样本：`workshop-facilitation` 复算 `高` vs 实档 [低]；
  `k6-performance`、`electron-best-practices`、`dependency-scan`、`pixel-perfect`、
  `version-management`、`secrets-scan` 复算 `中` vs 实档 [低]。
- **为什么校验器抓不到**：告警比的是「表内写的值 vs 复算值」，而迁报告的 worker
  **照复算值填** ⇒ 20 件全部 **0 告警**。真正该报的差异是「复算值 vs 问题节实档」，
  而 `SEV-01` 行与问题节之间**没有任何机器对照**。
- **为什么 `VOL-01`/`COV-01` 是主因**：`criteria-set.yaml` 的
  `VOL-01.band = 低..中`、`COV-01.band = 低..高` 两处区间上界各最高可抬一整档。
  慢变数据未外置（真档 [低]）⇒ 复算 [中]；标志性能力漏触发词（真档 [低]）⇒ 复算 [高]。
  上界取法当初是为「抓漏报」定向的，**在真实数据上它反过来制造了虚高**。
- **已裁定的二选一（采纳方案①，2026-10-04 落地）**：
  ① `SEV-01` 行改填**报告实档**，复算结果只作**独立的 `RECOMP` 参考行**（不覆盖答案）；
  ② 保留「表内填复算值」，但**必须同时机器对照问题节最高档**，不一致即红。
  ①改动小、语义干净；②能守住「不漏报」的原意但要求问题节也可机读。
- **验收**：任取本批任一件，把 `SEV-01` 行改回问题节实档 ⇒ 现行校验器 rc=0 零告警
  （即已复现「两条路都能过」）。裁定后应改成只有一条路能过。

#### B 已立：改成 `^##(?!#)[^\S\n]*[^\n]*?问题[^\n]*$`

停手线三项的满足方式：

1. **可复现 FAIL**：先把 `### 问题清单` / `##\n问题清单` / `  ### 问题清单` 补进
   `_FORM_FIXTURES["report-section.problem"]` 的**近邻反例**组，跑 `--selftest` ⇒
   **rc=1，断言④「全部近邻反例都不被误认」红**（证伪夹具，比合成 FAIL 更硬）。
   落地后转绿。**反向变异实测**：单独退回 `(?!#)`、单独退回 `\s*`，两处各自都被抓住。
2. **落盘证据行号**：形态行 `scripts/audit-criteria-set-check.py` 的
   `FORMS["report-section.problem"]`、夹具行 `_FORM_FIXTURES["report-section.problem"]`、
   切窗消费方 `max_finding_severity`。
3. **独立方审计通过**：verifier 独立复算 93 份差分（`max_finding_severity` 改变档位 **0**），
   并指出提案人漏看的**第三个近邻形态**——`##\n问题清单` 跨行（B1 只治了 H3 前缀、没治跨行，
   B2 一条改动同时封住两处，故选 B2）。

⚠ **收窄只改 `##` 后面那一个空白类**，标题内部那一段照旧（`## **问题与根因**` 三种写法一致命中）。

#### A 不立，并**否决我原先写的收窄方向**

审计实测推翻了我在 §8.17 初稿里写的方向：**`\s*` → `[ \t]*` 会引入回归**。
输入 `FOR-01 答\u3000「否」（全角空格 U+3000）时，`[ \t]*` 吃掉零个字符、全角空格落进取值类首位，
非贪婪 `+?` 凑够 1 字即满足 ⇒ 取值只剩一个 U+3000 ⇒ 下游 `strip()` 清空 ⇒
**这条引用被静默丢弃**（方向是**漏报**，最坏方向）。机制证据：`self_cited_answers` 的取值收尾。

正确方向是 **`[^\S\n]*`**（排除换行的空白类，保留 U+3000/U+000B），实测 0/93 差异。
**但仍不立**：A 的触发率 0/93 且缺陷**当前不可达**（唯一消费方 `self_cited_answers` 逐行扫描，
行内没有 `\n` 可吃）⇒ 零真实触发的防御性收窄，按纪律不立。

**顺带补了一条守门正例**（审计指出这是 `[ \t]*` 能在全绿下溜进来的结构性原因）：
`_FORM_FIXTURES["report-prose.cited-answer"]` 的正例组加了 `FOR-01 答\u3000「否」`。
原 6 条正例里**没有全角空格条目**——现在有人再想把空白类收窄成 `[ \t]*`，断言③/④ 会当场红。

**跨文件引用同步**：`report-template.md` 与 `criteria-set.yaml` 原有「形态清单以 `FINDING_ROW` 为准」
的指路语，形态表化后已成假陈述 ⇒ 改为指形态表 `FORMS`（`render-criteria-set.py --check` 仍 rc=0，
因该字面不进渲染产物）。`DESCRIPTION-AUDIT.md` 里的历史记述**不动**（那是当时的取证记录，改它等于篡改历史）。

### 8.18 「形态已穷举」这句话需要多少数据支撑（2026-10-05 · 用户质询后的实测）

用户质询：**正则性匹配需要足够的数据支持，只有本地这些数据不够扎实。** 下面是把这句话
拆成可回答的三问，以及**实测**给出的答案——其中一条是否定的，且否定得比预期更硬。

**新增两个实测脚本**（都是现取现用，语料本体不入库）：

- `scripts/form-shape-survey.py` —— 形态表**本库样本**的分布与残余检查
  （93 份报告 ＋ 夹具报告 ＋ 模板 = 全部自产件）。它把「穷举」变成可复核的问题：
  **列出所有含「问题」的标题行、聚类骨架、再把分不掉的余量显式打印**。
- `scripts/form-shape-external.py` —— **外部独立语料**（`corpus-list.py --remote` 现克隆，
  14 个独立仓 **793 件**）上量同样两类模式。

**实测一：外部语料对 `report-*` 各形态「不适配、不可评」。**
793 件第三方 SKILL.md 里，严重度记号 `[高/中/低/…]` 全文只出现 **3 次**；
判据集结果块**一件都没有**。⇒ 拿它给 `report-finding.*`、`report-table.answer-row`、
`report-head.*` 当分母，等于量「别人不这么写」，不是「我们写得对不对」。
这正是 `tests/corpus/SAMPLING.md` §二 说的「语料不适配，不可评」。

**因此：`FORMS` 里 `report-*` 形态的「穷举」，靠扩大第三方语料验证不了——不是样本不够，
是这类件第三方根本不写。** 这是本次实测最重要的一条结论，比任何触发率都重要。
能验证的只有两条路：①**对抗式构造语料**（按形态空间人工造件、声明期望判定）；
②**历史报告**（跨模板版本的全量自产件）。**本轮只把①的路铺好（脚本与判定口径），
尚未造件 ⇒ 形态表当前只能称「在自产件上已穷举」，不能称「已穷举」。**

**实测二：同源样本的方差方向是错的。**
`form-shape-survey.py` 实测：93 份报告里档位记号的**前缀骨架有 320 种**，
但其中绝大多数是**散文里提及 `[低]`**（叙述），不是发现标记。
⇒ 93 份同源报告不是「方差小」，是**方差被叙述噪声灌满、且与形态表要的子集不对齐**。
拿它证明「形态就这三种」是无效推理。

**实测三：一条不可外推的边界（收窄时务必带上）。**
外部语料里问题类标题的深度分布实测为
`{H1:15, H2:34, H3:46, H4:16, H5:6}`——**H3 最多、H2 反而少**。
⇒ 本轮 §8.17 B2 的 `^##(?!#)` 是**本库报告约定**下的判断，
**不是**「问题节就该在 H2」的通用结论；任何跨库复用都不得照搬。

**顺带把 §8.17 的措辞收紧**：那两条候补的「实测并存三种编号」等表述，
其样本是 93 份**同源**报告，只能支持「自产件长这样」；引用时须带上这一限定。

### 8.19 对抗式构造语料测出的形态缺口（2026-10-05 · 规则 11 候补，**当轮不修**）

`§8.18` 判定「93 份同源报告」与「793 件外部语料」**两条路都证明不了形态穷举**，
只剩下的第三条是**按形态空间人工造件**。本轮把这批件建起来了：
`tests/form-corpus/cases.yaml`（判据数据）＋ `scripts/form-corpus-check.py`（判定器）
＋ `tests/form-corpus/README.md`（构造规则）。

**语料的鉴别力恰恰体现在会红**：造出来的件里有一批形态表现在就抓不住。
`form-corpus-check.py` 把这些缺口从「不知道」变成**具名、可数、有据**——
每条缺口一个 `gap_id`，且脚本强制该编号**在治理记录里真实存在**，
指不到号的账不算数（这条不变量本轮当场把 15 条未登记的 `gap_id` 判成语料自身不合规）。

#### 缺口登记（编号即 `cases.yaml` 的 `gap_id`；条数以 `form-corpus-check.py` 实算输出为准）

| `gap_id` | 形态 | 缺口 | 失效方向 | 风险 |

#### 为什么当轮不修

改这九条都是**改判据**，撞停手线（可复现 FAIL ＋ 落盘证据 ＋ 独立审计通过）。
本轮只把证据备齐：每条缺口都有 `cases.yaml` 里**预先声明的期望**（不是事后补的），
可复现 FAIL 由 `python3 scripts/form-corpus-check.py` 产出，落盘证据即该 YAML 行号。
**缺独立审计这一项，所以一条都不落地。**

⚠ **风险最高的两条建议优先**：`R-01`（误伤，一份合规报告恒红）与 `F-02`/`F-01`/`F-04`
（漏报，核心的「档位唯一实源」保证被绕过）。合起来占了这批缺口的**方向性风险**——
一条误伤、四条漏报。

#### 这批件本身的边界（诚实交代）

- 语料是**本库自造**的短片段，形态由我按「人可能这么写」推演，**不是从真实报告里统计出来的**。
  所以它测的是「形态表对**我设想得到的**形态空间有没有鉴别力」，
  **不是**「真实世界的形态空间已经穷举」——后者仍然没有证据。
- `permitted: false` 的件是**护栏**：骨架本就不允许的写法，「不认到」是正确行为。
  它们的作用是**锁住安全方向**（例如 `sec-05`/`sec-06` 锁住 §8.17 的 B2 收窄不被回退），
  **不计入缺口**。脚本对此有硬断言：护栏件不得标 `known_gap`。
- 因此形态表当前可以声称的上限是：**「在自产件上已穷举，且对本批对抗语料的 N 件有鉴别力」**，
  其中 N 由 `form-corpus-check.py` 实算；**不能**声称「形态已穷举」。

### 8.20 档位实源缺陷的可复现证据（2026-10-05 · **设计件已删，此处留证据**）

> 原设计件 `design/skill-description-audit/` 已按用户裁定整目录删除（机制设计早于模型定稿、
> 依据已作废）。但下面两样是**关于现有实现的实证事实，与设计版本无关**，故留在本记录。

#### 缺陷本体（可复现 FAIL）

校验器把档位**声明值**（`SEV-01` 行）与**解析「五、问题」散文重算值**作硬失败比对。
把一条 `[中]` 发现的 Markdown 列表记号去掉（**档位与内容一字不动**），重算认不到该形态 ⇒
回落更轻档 ⇒ 硬失败，文案是「**请改发现而不是改本行**」。**三项后果同时发生**：

1. **静默降级** `[中]`→`[低]`；
2. **方向是报轻**（漏报，最坏方向）；
3. **要求审计员改自己的结论去迁就解析器**。

复现（真源不动，全程 `/tmp` 副本）：把 `skill-description-audit/DESCRIPTION-AUDIT.md` 里
`1. **[中]** description 未声明…` 改成 `**[中]** description 未声明…`，再对该副本跑
`audit-criteria-set-check.py` 的 `check()`，problems 由 2 条变 3 条，新增即此条。

**根因是模型缺陷不是实现缺陷**：判决放在记账层，而形态空间无下界，洞的方向取决于落在哪一档。
修法须在领域模型定稿后重新推导（**当时**设计件被删；⚠ 现况已变：`design/skill-description-audit/MODEL.md` 已重写并在册，本句是 §8.20 出具当时的快照，不是现状——2026-10-05 分工 B 要求标注失效）。

#### 独立审计已确认的六条缺陷（针对已删除的那版设计）

1. 验收「删掉形态表后对抗语料仍全绿」是**假陈述**——实测三条发现形态退出服务后
   `form-corpus-check.py` rc=1（退化规则触发）；`form-corpus-check.py:101` 硬判「form 不在形态表里」。
2. 验收「记录表条数 == 散文条数」**无鉴别力**——数散文条数本身就是形态匹配。
3. 渲染锚点自相矛盾（「由判据集渲染」又「勿手改」）——审计员数据若被渲染会**覆盖人工填写**。
4. **过度设计**：改判据集契约才是撞停手线的原因，收益并不需要它。
5. **迁移矛盾**：证据格判硬失败会把存量 21 份全打红，与「不整轮重做」自相矛盾。
6. 用户可见报错文案引用 INV-8 作依据，而该不变量**禁止**此行为 ⇒ 文案本身是假陈述。

### 8.21 判据退役引发的**散文面**假陈述（2026-10-05 · 独立审计抓出，**只登记未改**）

本轮把 5 道判据标为作废（`COV-01` `VOL-01` `COV-03a` `COV-03b` `COV-03c`，
理由＝对无界集合问全称/存在量化，正面答案不可证伪）。

`parse_criteria_set` / `render_table` / `recompute_sev` / `check` **全都照读**
⇒ **标了作废的题仍在表里、仍须作答、仍参与 band 包络。那是标签，不是退役。**
本轮已修：`parse_criteria_set` 跳过作废题、`render_table`／`render_template_rows` 不渲染、
`selftest` 加断言「作废题不在解析结果里」。变异自证：把 `COV-01` 改回现行 ⇒ 门禁红。

**但还有一层没修，且没有任何机制拦**：

> **退役一道判据，还要改 `SKILL.md` 里解释它的散文。**
> 出具当时（§8.21 那轮）`SKILL.md` 里有 20 行把已退役的题当现行在讲。
> ⚠ **那是当时值，不是现状**（2026-10-05 第六轮独立审计分工 B 判该句为假：现在时态＋逐行清单
> ＝可复核断言，而复核为零）。**现值实算＝0 处 / 0 行**——口径：作废题 ID 取自
> `criteria-set.yaml` 的 `status: 作废`（不在脚本或注释里另列一份），扫
> `SKILL.md`／`criteria-methods.md`／`report-template.md`／`patterns.md` 均 0 命中。
>
> **判据退了，讲解它的文字没退 ⇒ 技能文档在教人用一道不存在的判据。**

⚠ **这与 8.19 记录的「机器管不到散文」是同一个洞的第三个面**：
`render --check` 只比对渲染块，**散文面（`SKILL.md` 正文、`references/*.md`）完全无人管**。
三个面分别是：形态（已有形态表＋对抗语料）、格绑定（已有 `cell` ＋渲染）、
**散文（无任何机制）**。

**处置三选一（待用户裁定）**：
1. **判据退役时**同步改散文，并加**扫描断言**：`SKILL.md`／`references/` 里不得出现
   `status: 作废` 的判据 ID（闭集外硬失败）——**这是最小可行解**；
2. 把讲解从 `SKILL.md` 移到**由判据集渲染**（讲解与判据同源，退役自动连带）；
3. 接受假陈述，靠人工记住同步（**不建议**：已实测漏过一次）。

**本轮只登记不修**——改 `SKILL.md` 正文属契约件，且方案 1/2 代价差很大。

### 8.22 逐题讲解外置（2026-10-05 · `LEN-03` 由红转绿）

**起因**：`LEN-03`（正文 ≤500 行）在本技能上**判 False，实算 649 行**。
成因不是散乱，而是**逐题讲解（304 行）＋ FOR-01 判定分支（41 行）**占了大头。

**一个必须记的教训**：`LEN-03` 在此之前**一直是假通过**——它用 `raw.split("---")` 取正文，
而本仓 `SKILL.md` 里有 58 处水平线 `---` ⇒ 切出来的「正文」只有 68 行。
**一个因为量错对象而假通过的检查，比没有检查更坏**（它让人以为这一维已被覆盖）。
已改用 frontmatter 感知切分（`split_skill`：按**文件开头**的 `---` 到下一个 `---`）。

**处置：外置，且用户裁定了取舍**。我的反对意见是「外置讲解会破坏判题可读性」，
**用户驳回**：「外置只是多跳转一次，而且本技能是 `disable-model-invocation: true`
（仅用户显式调用），正文只在显式调用时加载，**多一跳的实际成本很低**」。
⇒ 我的反对不成立：**成本是显式调用时付的，而调用是人主动发起的**。

**落地**：
